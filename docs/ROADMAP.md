1. 프로젝트 개요

ServeStream Reborn은 기존 ServeStream 오픈소스 프로젝트를 기반으로 현대적인 Android 환경에 맞게 재탄생시킨 인터넷 라디오 및 스트리밍 플레이어다.

기존 소스코드를 유지하면서 UI, 재생 엔진, 다국어, 최신 Android 호환성을 개선하는 것을 핵심 방향으로 한다.

범용 동영상 편집기나 일반 음악 플레이어로 확장하기보다는 인터넷 라디오와 네트워크 스트리밍이라는 본래 정체성을 유지한다.

개발 기본 원칙

1. 기존 소스코드와 구현된 기능을 최대한 보존한다.
2. 현재 UI 디자인을 불필요하게 변경하지 않는다.
3. 기존 방송국 데이터와 설정의 호환성을 유지한다.
4. FFmpeg 재생 엔진을 안정적으로 발전시킨다.
5. 최신 Android 및 폴더블 기기를 지원한다.
6. 다국어 지원을 유지하고 번역 완성도를 높인다.
7. 실제 구현 및 테스트가 완료된 기능만 지원한다고 표시한다.

2. 현재 프로젝트 현황

GitHub CHANGELOG 기준 최신 버전은 2.3.8이다.

이미 구현된 주요 기능:

- Material 3 기반 UI
- 시스템 / 라이트 / 다크 테마
- 한국어, 영어, 일본어, 중국어 등 다국어
- FFmpeg 7.1.1 기반 재생 엔진
- HTTPS 및 TLS 스트리밍
- HTTP ↔ HTTPS 리다이렉트 처리
- 플레이어 자동 재시도
- 자동 재연결 최대 10회
- 백그라운드 재생
- 잠금 화면 및 퀵패널 미디어 컨트롤
- 블루투스 미디어 버튼
- 방송국 백업 및 복원
- 재생 오류 보고 및 진단 기능
- 고정 서명 키를 통한 업데이트 설치

현재 APK에서 확인한 네이티브 ABI는 다음과 같다.

- arm64-v8a
- armeabi-v7a

현재 FFmpeg 구성은 라디오 재생 중심으로 경량화되어 있다.

FFmpeg CLI, FFprobe, 전체 필터 및 인코딩 기능은 별도로 확인하고 필요한 경우에만 추가한다.

3. FFmpeg 엔진 고도화

3-1. 기본 방향

기존 FFmpegMediaPlayer 및 JNI 구조를 우선 유지한다.

무조건 FFmpeg CLI 기반으로 전면 교체하지 않는다.

현재 재생 엔진의 안정성을 유지하면서 필요한 기능을 단계적으로 추가한다.

3-2. 업그레이드 목표

- FFmpeg 8.x 계열 업그레이드 검토
- 최신 Android NDK 적용
- OpenSSL 업데이트 검토
- HTTPS 및 TLS 호환성 강화
- JNI 메모리 관리 개선
- 스트림 종료 및 재연결 시 리소스 누수 방지
- FFmpeg 오류 로그 개선
- libavfilter 추가 검토
- FFprobe 또는 libavformat 기반 스트림 분석

3-3. 코덱 지원

라디오 중심으로 다음 코덱의 실제 디코딩 지원을 검증한다.

- MP3
- AAC / AAC+
- HE-AAC
- FLAC
- Opus
- Vorbis
- AC-3
- E-AC-3
- PCM
- AMR
- WMA

코덱별 실제 지원 여부를 테스트하고 앱 내부에 정확하게 표시한다.

3-4. 스트리밍 프로토콜

- HTTP
- HTTPS
- HLS / M3U8
- RTSP
- RTMP
- 기타 FFmpeg가 지원하는 네트워크 프로토콜

각 프로토콜은 실제 재생 가능 여부를 검증한다.

4. 스트리밍 안정성 개선

우선순위가 높은 핵심 작업이다.

- 자동 재연결 기능 개선
- 재연결 간격 사용자 설정
- 연결 시간 초과 설정
- HTTP 리다이렉트 개선
- HTTP User-Agent 설정
- 사용자 지정 HTTP 헤더
- Cookie 및 인증 토큰 지원
- HTTP 403 / 404 / 429 / 500 오류 처리
- 네트워크 전환 시 재생 복구
- Wi-Fi와 모바일 데이터 전환 대응
- 방송국별 재생 오류 기록
- 버퍼링 상태 표시
- 연결 상태 및 스트림 정보 표시

특히 방송국마다 서버 환경과 인증 방식이 다르므로 다양한 스트리밍 서버에 대한 호환성을 확보한다.

5. 방송 메타데이터 및 시각적 개선

5-1. ICY 메타데이터

- 현재 재생 중인 곡 제목
- 아티스트 이름
- 방송국 이름
- 방송 프로그램 정보
- 메타데이터 변경 이벤트 처리

5-2. 앨범 아트 및 방송국 이미지

- 방송국 로고 표시
- 앨범 아트 표시
- 곡 정보에 따른 이미지 갱신
- 이미지가 없는 방송의 기본 이미지
- 네트워크 이미지 캐싱

이미지 검색 서비스는 선택적으로 제공하고 외부 API 오류가 재생을 방해하지 않도록 한다.

6. 방송국 관리 기능

- 방송국 카테고리 및 폴더
- 즐겨찾기
- 최근 청취 목록
- M3U 가져오기 및 내보내기
- PLS 가져오기 및 내보내기
- OPML 가져오기
- 중복 URL 검사
- 방송국 데이터 백업 및 복원
- 방송국 목록 일괄 관리

기존 방송국 데이터베이스와 백업 파일의 하위 호환성을 유지한다.

7. 오디오 기능 개선

인터넷 라디오 청취 경험을 개선하는 범위에서 구현한다.

- 이퀄라이저
- 저음 및 고음 조절
- 음량 정규화
- 오디오 리샘플링
- 오디오 버퍼 설정
- 음량 조절 및 음소거
- 오디오 포커스 개선

외부 이퀄라이저 라이브러리를 추가할 때는 기존 재생 엔진과의 충돌을 확인한다.

최우선 장기 개발 과제

Google Android Developers 공식 발표 기준으로 다음 일정을 준수한다.

2027년 4월

일반 앱은 최소 Tier 3 Adaptive Ready 기준을 충족해야 한다.

- 레터박싱 없이 가용 화면 영역 사용
- 접기 및 펼치기 시 상태 유지
- 회전 및 화면 크기 변경 대응
- 입력 내용과 스크롤 위치 유지
- 미디어 재생 상태 유지
- 멀티 윈도우 지원
- Google Play 등록 시 폴더블 스크린샷 3장 제출

2027년 8월

Google Play 신규 앱 및 업데이트 앱은 Android 17에 해당하는 Target API 37을 충족해야 한다.

대화면 앱의 화면 방향 및 크기 조절 제한과 관련된 기존 우회 설정도 점검한다.

가능하면 Tier 2 Adaptive Optimized 수준을 목표로 한다.

8-3. 가로 모드

- 가로 화면 최적화

9. 폴더블 테스트 및 Google Play 제출 자료

다음 세 가지 폴더블 화면 비율을 대상으로 테스트한다.

1. 1:1 펼친 내부 디스플레이
2. 4:3 펼친 내부 디스플레이
3. 10:16 접힌 외부 디스플레이

Google Play 제출용으로 다음 자료를 준비한다.

- 일반 스마트폰 스크린샷 2장

- 4:3 폴더블 스크린샷 1장
- 10:16 접힌 화면 스크린샷 1장

실제 앱 실행 화면을 Android Emulator 또는 실기기에서 캡처한다.

10. Android 및 네이티브 호환성

ABI 확대

현재 지원 ABI를 유지하면서 다음 네 가지를 목표로 한다.

- arm64-v8a
- armeabi-v7a
- x86
- x86_64

FFmpeg뿐 아니라 모든 JNI 및 외부 네이티브 라이브러리의 ABI 호환성을 확인한다.

16KB 메모리 페이지

- NDK r28 이상 검토
- 모든 네이티브 라이브러리 정렬 검사
- ELF LOAD 세그먼트 검사
- APK 패키징 정렬 검사
- 실제 16KB 환경 테스트

Android 최신 버전

- Android 15 이상
- Android 16
- Android 17 / API 37

백그라운드 재생, 미디어 포그라운드 서비스, 알림 및 저장소 정책을 점검한다.

빌드 오류가 발생하면 원인을 분석하고 수정한 후 다시 테스트한다.
